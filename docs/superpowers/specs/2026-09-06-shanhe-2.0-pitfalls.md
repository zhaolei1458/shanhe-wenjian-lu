> 红线、纪律、坑、验收标准、风险与对策
> 老奴把上回踩过的坑、这回要躲的坑，全记在这儿

## 一、红线（不能破的规矩）

### 1.1 纯文字武侠的皮

- **不贴血条经验条的网游脸**——属性、修为、银钱回到明面，但藏在「翻开账本看」的面板里，不是贴脸的血条经验条。
- **水墨字海照旧当主舞台**——正文、输入、按钮都按书卷皮排，不改成网游 UI 脸。
- **打字见真章**——意头输入仍是主交互，按钮是扶手不是主菜。

### 1.2 主角一条命，玩得好不必死

- **寿元是软计时，不是催命符**——修为跟不上才老死，不是到点就死。
- **重生是败者的退路**——只有意外横死、走火入魔、修为没跟上老死了，才走转世投胎。它不是日常流程，是「输了」才走的路。

### 1.3 主线两截

- **身世局开路**——出身给一段剧本式身世局（每人不同），有分幕有岔路有硬仗有揭破。
- **长生局收尾**——破了身世局，接上长生登顶的后半段主线，一路把人引向仙界、幽冥、界外。

### 1.4 移动端优先

- **拇指区在底部**——底导航、面板入口都在屏幕下半部，手机上单手能操作。
- **面板是覆盖层，不是跳转**——点图标弹出面板，点「收」收回，不要跳页。
- **按钮大小、间距、触摸反馈**——手机上点得着、不卡、有反馈。

## 二、纪律（写代码的规矩）

### 2.1 同文件编辑必须串行

- **铁律**：同一文件的多次 Edit 必须一次一个 tool call，等回执、grep 验证，再发下一个。
- **教训**：上回同文件并行 Edit 吃掉两处（state.js/legacy.js），回执「Successfully edited」≠落盘。

### 2.2 内容层引用的字段必须逐一对照引擎消费面

- **铁律**：内容层写的字段（如 `effect.combat`），引擎必须读（如 `opt.combat`）。
- **教训**：上回事件选项 `effect.combat` 引擎不读，战斗全死。

### 2.3 测试断言先写「引擎真实形状」

- **铁律**：断言先 grep 看真实字段名（如 `pending.ev` 不是 `pending.title`），再写断言。
- **教训**：上回对着想象写 JSON.includes，断言全绿但内容没到。

### 2.4 扩桩文件的 `Object.assign` 合并行写在文件尾

- **铁律**：扩桩文件（如 adventures15.js）末尾必须 `Object.assign(ADVENTURES, ADVENTURES15)`，否则内容层加载了但主表里没有。
- **教训**：上回闸六 n=138 即此坑。

### 2.5 测试闸里所有异步段必须在汇总前被 await 到

- **铁律**：异步 IIFE 必须 `await`，否则失败被吞、退出码 0。
- **教训**：上回闸八写成异步 IIFE 后，顶层汇总不等它执行。

### 2.6 新事件通路接入时，凡是「死亡后仍为真」的状态，下游事件掷签必须查 afterlife

- **铁律**：`rollNodeEvents` 等调用点，查 `this.afterlife`，防止幽冥余程中继续 rollNodeEvents 覆盖 pending。
- **教训**：上回十一期修的是幽冥 alive 语义，十四期修的是 alive 常态，同根同源。

### 2.7 fireEvent 的调用点都要问一句「玩家手上有没有幕」

- **铁律**：`yearTick` 等调用 `fireEvent` 前，查 `!this.pending`，防止大事抢幕覆盖玩家手上未结事件。
- **教训**：上回十四期修掉一个潜伏真 bug。

## 三、坑（上回踩过的坑，这回要躲）

### 3.1 战斗系统死了

**上回的坑**：
- 事件选项 `effect.combat` 引擎不读，只读 `opt.combat`
- 全内容只有 1 桩奇遇真能打

**这回要躲**：
- 任务 2.3 修战斗核时，先 grep 看 `applyEffect()` 读什么字段，再改内容
- 11 个战斗模板全接进事件选项顶层 `opt.combat`
- 验收：打「拔刀」真进入战斗

### 3.2 人生节点死代码

**上回的坑**：
- `checkLifeNodes()` 只被定义，全仓库无调用点
- 16 出身都配了 `lifeNodes` 数据，但从不触发

**这回要躲**：
- 任务 1.2 写主线时，用 `quest.js` 的任务日志系统，不用 `checkLifeNodes()`
- 但保留 `lifeNodes` 数据，未来可能用

### 3.3 银钱可负且不可见

**上回的坑**：
- `applyEffect` 对 `ef.money` 直接加减、无下限
- UI 不显示银钱，玩家背着隐形债务还不知为何「没钱」

**这回要躲**：
- 任务 2.1 属性面板里加银钱显示
- `applyEffect` 里加银钱下限检查（不能负）

### 3.4 破境门槛不透明

**上回的坑**：
- 筑基以上必须在灵地/海底/仙山等节点才可破，否则卡在临界并只给一段语焉不详的提示
- bot 常驻市镇做工→打坐 100% 被「此地嘈杂」挡回→xiwei 恒为 0

**这回要躲**：
- 任务 3.2 破境续命时，破境失败给明确提示（「此处气机浮杂，需寻灵地」）
- 任务日志里加「寻访灵地」任务，牵着人去

### 3.5 自然语言命中率低

**上回的坑**：
- 导航必须在「当前节点 links 的邻接去处/整座城市名」里点名
- 想「出村去东市」必须一级级走图；跨城必须说整城名

**这回要躲**：
- 任务 0.2 光阴行动核里，保留旧 parser 的宽解析（出门/出去/上街→闲逛）
- 加「去 X」的直达解析（如「去天启城」直接 travel）

### 3.6 事件挂起时仍可自由输入

**上回的坑**：
- `input()` 只在战斗态和数字选号处短路，未检查 `this.pending`
- 事件模态下输入「看看四周/闲逛」会走正常动作并可能 `rollNodeEvents` 用新事件盖掉当前 `pending`

**这回要躲**：
- 任务 0.2 光阴行动核里，`input()` 开头查 `this.pending`，有幕则短路

### 3.7 固定文本复读

**上回的坑**：
- `doWait`/`doEat`/`doBuy` 写死同一句，无 freshText 保鲜

**这回要躲**：
- 任务 0.2 光阴行动核里，保留 `freshText()` 机制

### 3.8 生成批奇遇灌水

**上回的坑**：
- 698 桩生成奇遇，通篇「某人的话糙理却直」同一句套路
- 格言金句重复几十遍，选项只有「好心+1悟性 / 敷衍+1悟性」

**这回要躲**：
- 设计文档已定：698 桩生成灌水奇遇不当主食，先压箱底降权
- 任务 4.1 内容翻译层里，只接 302 桩手写奇遇当支线
- 未来要接生成批，先逐批重写或精修

### 3.9 内容和内容互不相认

**上回的坑**：
- 门派、装备、妖兽、奇遇各有各的文本，彼此几乎不点名
- 打了一场漂亮仗，不会让你拿到那门派的绝学

**这回要躲**：
- 任务 2.3 战斗核里，打赢恶人掉落他门派的功法
- 任务 4.1 内容翻译层里，奇遇奖励和门派、装备、妖兽咬合

### 3.10 一世拖得太长

**上回的坑**：
- 没有「闭关数月」这类跳时间通道
- 一世自然老死要几千次操作，普通玩家一场根本走不到盖棺

**这回要躲**：
- 任务 0.2 光阴行动核里，加「闭关 N 年」「养伤 N 月」动作
- 任务 3.1 寿元压力里，老死前 10 年给预警文字

## 四、验收标准

### 4.1 每层验收指标

**看的不是「测试全绿」，是下面这三个数**：

1. **主线推进率**：盲玩 40 分钟内，机器人 / 真人走到第几幕？
2. **真打了几场架**：战斗核是不是真的在用？
3. **玩家感没感觉到变强**：面板里的数字 / 武学 / 装备，有没有在涨？

### 4.2 每层验收清单

**第零层**：
- 手机上新角色走几步不卡
- 五本面板翻得开
- 存档读档不丢

**第一层**：
- 真人盲玩 40 分钟内能被这条主线一路拽到高潮
- 中途会悬心、会拍腿，不会干瞪眼不知道干嘛

**第二层**：
- 玩家走完「初出茅庐 → 学会本事 → 变强 → 打赢关键一战」
- 赢了有缴获、输了会受伤会怕死

**第三层**：
- 会玩的玩家能一路破境活下去、望得见更上层楼
- 玩砸的老死走转世，转世后能感到「上一世的东西还跟着我」

**第四层**：
- 压箱底的手写奇遇、事件经翻译层分批接成支线和路上调味
- 再铺 1～2 个出身，验证「每人不同主线」真立得住
- 仙界幽冥边域按登顶路接入
- 移动手感、音效、成就、发布收尾

## 五、风险与对策

### 5.1 风险：新内核太重，工期爆

**对策**：
- 严格按五层工期推进，每层验收过了再进下一层
- 第一层（一条身世局做到高潮）是最要紧的一层，验证过了后面全是铺量；这一层没对味，改的就是一个人一个局，成本小

### 5.2 风险：移动端适配难

**对策**：
- 任务 0.1 先做底导航框架，手机上试
- 任务 4.4 再做移动手感优化
- 中间每层验收都手机上试

### 5.3 风险：战斗核修不通

**对策**：
- 任务 2.3 战斗核修复是大头（6 小时），先 grep 看真实字段名
- 修不通就降级：先做「文字描述的战斗」（如「你拔刀，他闪避，你砍中他肩膀，他 HP -20」），不做回合制

### 5.4 风险：任务日志系统复杂

**对策**：
- 任务 1.1 任务日志系统先做最小可用版（任务列表 + 目标检查 + 奖励发放）
- 不做复杂的「任务链」「分岔选择」，先跑通一条线性主线
- 未来再扩

### 5.5 风险：内容翻译层写不动

**对策**：
- 任务 4.1 内容翻译层先做最小可用版（只翻 302 桩手写奇遇）
- 不翻 698 桩生成批
- 翻译层写不动就降级：直接把旧内容当支线任务数据，不做翻译
