# 设计文档 · 存档导出与导入（二十期 A 卷）

> 状态：**定稿即实现口径**。本文档是实现的唯一依据；实现与文档冲突时，改代码不改文档（除非发现文档自相矛盾，那时先改文档）。

## 一、目标与不做什么

**目标**：换机器、清浏览器数据、备份进度时不丢一世文字与往世簿。导出一个文件即整卷带走，导入即整卷还原。

**不做**（明确划界）：
- 不做云同步、不做多文件管理（一次一个 `.shanhe.json`）。
- 不做「选择性导入」（挑某几个档位）——选择越多，心智负担越重，且合并语义会烂。
- 不加密。存档是玩家自己的东西，不是需要守的东西；但文件开头带可读标识，肉眼能认。

## 二、导出格式规范（fmt 1）

文件名：`山河问剑录·存档-YYYYMMDD-HHmm.json`（时间取导出时刻本地时间）。

```json
{
  "game": "shanhe-wenjian-lu",
  "fmt": 1,
  "exportedAt": "2026-09-05T20:00:00+08:00",
  "meta": { ...完整传承层对象，原样... },
  "saves": [
    { "slot": "auto",  "name": "李观棋·43岁", "at": 1790000000000, "state": { ...完整 state... } },
    { "slot": "slot1", ... }
  ]
}
```

字段规约：
- `game`：魔数。不是这个串的文件，导入器一眼拒收。
- `fmt`：格式版本整数。当前 1。未来 schema 变更时递增，导入器只认 `<= 当前最大可解版本`。
- `meta`：`Save.loadMeta()` 的原样对象（legacyPoints / pastLives / crossSeenAdventures / codex / wellTokens / …）。**不裁剪不重排**——meta 是活的，导出器不知道未来会加什么字段，原样携带最诚实。
- `saves`：`Save.listSaves()` 的全量拷贝。`state` 内含 `_journal/_pending/_worldQueue/_uiMode`（十五期投影），因此导出档自带「本世文字卷轴」。`at` 毫秒时间戳原样。

## 三、导入语义（关键裁定）

**导入 = 整卷替换 + 导入前自动备份。** 不做合并。理由：
1. pastLives / codex 没有稳定唯一键，按启发式合并会出现重复章、重复判词——错比丢更伤。
2. 玩家导入的场景只有两个：换机器（替换天经地义）、抢救坏档（更不允许半吊子合并）。

流程：
1. 解析 + 校验（见 §四）。失败则**什么也不动**，报错文案说人话。
2. 校验通过 → 先把当前 meta 原样写入档位 `backup-preimport`（普通档位，往世簿里可见可读，玩家自己决定删不删）。
3. 逐个写入导入档的 saves（原 slot 名）。
4. 整体替换 meta。
5. 刷新档位列表，播一条确认文案（含：带回几世、几个档位）。

**校验失败绝不落一笔**——导入是事务，不是流水账。

## 四、校验规则（validateImportDoc，纯函数）

按序检查，返回 `{ ok, error, summary }`：

| # | 规则 | 失败文案（原文入 UI） |
|---|---|---|
| 1 | JSON.parse 通过 | 「这不是一份能读的存档文件。」 |
| 2 | `game === 'shanhe-wenjian-lu'` | 「这不是山河问剑录的存档。」 |
| 3 | `fmt` 为 1..99 的整数 | 「存档格式认不出来。」 |
| 4 | `meta` 是对象且含 `legacyPoints` 数值 | 「存档里的往世簿缺了页。」 |
| 5 | `saves` 是数组；每项有 `slot`（字符串）、`state.life.name`、`state.world` | 「第 N 个档位残了，缺了名姓或世界。」 |
| 6 | 全部通过 | ok；`summary = { lives: meta.pastLives.length, slots: saves.length, names: [各档 name] }` |

`fmt > 1` 的宽容策略：fmt 2/3 的文件如果有 meta.legacyPoints，按 fmt 1 尽力读（向后兼容读，不向后兼容写）；连 legacyPoints 都没有才拒。

## 五、纯函数分层（可测性）

`src/save/port.js` 只依赖注入的 Save 接口，不摸 IndexedDB：

```
buildExportDoc(meta, saves) -> doc          // 纯
validateImportDoc(parsed) -> {ok,error,summary}  // 纯
exportToFile(doc)            // 浏览器侧：Blob + a[download]，node 下跳过
importAll(saveLike, doc)     // saveLike 注入 {saveGame, saveMeta}，node 测试用假件
```

闸测覆盖纯函数三件 + importAll 用假 Save 验证「备份→写档→写 meta」顺序与失败不落笔。

## 六、UI（标题屏「档管」折叠区）

- 标题屏新增一行折叠入口「档管 · 备份与还档」。
- 展开：`导出整卷` 按钮（有 meta 或有档位即可点）；`导入存档` 触发文件选择。
- 导入两步确认：选文件后先显示预览（历世 N 世 · 档位 M 个：名字列表）+ 警示「导入会整卷替换现有进度（当前进度自动备份到『backup-preimport』档）」，确认按钮「还档」，取消按钮「算了」。
- 结果文案走标题屏现有 `legacy-line` 下方一行提示区。

## 七、验收标准

1. 导出→清库→导入，历世数/家底/图鉴/各档位卷轴逐字还原。
2. 坏文件（非 JSON/错魔数/缺 meta/档位残）四种全部拒绝且零落笔。
3. 导入前 backup-preimport 必有当前 meta。
4. 闸二十全绿；node 环境纯函数可测。
